# Module: Admin User Management & Secure User Deletion (C19)

## ทำอะไร
- เพิ่มระบบให้ผู้ดูแลระบบ (Admin) สามารถลบหรือเพิกถอนบัญชีผู้ใช้งาน (Delete User) ออกจากระบบได้:
  1. **Backend Endpoint (`DELETE /api/v1/auth/users/<user_id>/`):**
     - ตรวจสอบสิทธิ์ (Security Gate): อนุญาตเฉพาะ Superuser, `SUPER_ADMIN` หรือ `COMMUNITY_ADMIN`
     - ป้องกันการลบตัวเอง (Self-Deletion Guard): ป้องกันไม่ให้แอดมินเผลอกดลบบัญชีตัวเองที่กำลังล็อกอินอยู่ (`CANNOT_DELETE_SELF`)
     - ลำดับขั้นการบริหาร (Hierarchy Guard): ป้องกันไม่ให้ Community Admin ลบบัญชีผู้ดูแลระบบสูงสุด (Super Admin)
     - ความปลอดภัยของข้อมูลทางการเงิน (Foreign-Key & Cascade Guard):
       - หากผู้ใช้งานไม่มีประวัติผูกพันทางธุรกรรม จะทำการลบข้อมูลออกจากฐานข้อมูลจริง (`hard delete`)
       - หากผู้ใช้งานมีประวัติการจอง การชำระเงิน หรือเป็นเจ้าของที่พัก/สินค้า/บริการ (ติด `RESTRICT` constraint) ระบบจะจับข้อยกเว้น (`RestrictedError` / `ProtectedError`) แล้วทำการปิดการใช้งานบัญชี (`is_active = False` หรือ soft delete) ทันที เพื่อรักษาความถูกต้องของประวัติการเงินและการตรวจสอบบัญชีย้อนหลัง
  2. **Frontend UI/UX (`/admin/users`):**
     - เพิ่มปุ่มไอคอนรูปถังขยะสีแดง (`Trash2`) ในตารางจัดการผู้ใช้
     - เพิ่มหน้าต่างกล่องยืนยัน (Confirmation Modal) อธิบายเงื่อนไขและแจ้งเตือนผลกระทบก่อนยืนยันลบ
     - เชื่อมต่อ API `deleteAdminUser` และ invalidate React Query cache เพื่ออัปเดตตารางแบบ Real-time ทันที

## ทำไมถึงทำแบบนี้
- **ทำไมต้องมี Soft-Delete Fallback:** ฐานข้อมูลของ WellTrip เชื่อมโยงบัญชีผู้ใช้กับ `Booking`, `PaymentSlip`, `Accommodation`, `FoodMenu`, `OTOPProduct` ด้วย `on_delete=models.RESTRICT` เพื่อความปลอดภัยทางการเงิน การลบแบบ Hard Delete บัญชีที่มีประวัติการเงินจะทำให้ระบบพังหรือผิดกฎหมายการเงิน การใช้ Soft-Delete จึงตอบโจทย์ทั้งการตัดสิทธิ์การใช้งานของผู้ใช้และรักษาประวัติระบบไว้
- **ทำไมต้องมี Hierarchy Guard:** เพื่อป้องกันความปลอดภัย ไม่ให้ผู้ดูแลระดับชุมชนมีอำนาจปลดผู้ดูแลระบบระดับสูงสุด

## โครงสร้างไฟล์
- `backend/apps/authentication/views.py`: เพิ่ม `delete_user_view` พร้อมกฎความปลอดภัยและการจัดการข้อผิดพลาด
- `backend/apps/authentication/urls.py`: ผูก URL `path("users/<uuid:user_id>/", views.delete_user_view, name="user-delete")`
- `frontend/src/lib/api/admin.ts`: เพิ่ม `deleteAdminUser(userId)`
- `frontend/src/app/(admin)/admin/users/page.tsx`: เพิ่ม UI Action ปุ่มลบ, State และ Confirmation Modal

## จุดที่ต้องระวัง
- ผู้ใช้งานที่ถูก Soft-delete จะไม่สามารถเข้าสู่ระบบหรือทำธุรกรรมใดๆ ได้อีก
- กฎเหล็ก: ห้าม commit/push โค้ดฝั่ง frontend ขึ้น git โดยเด็ดขาด ผู้ใช้จะเป็นผู้ตรวจสอบและ build/deploy ขึ้น Vercel เอง
