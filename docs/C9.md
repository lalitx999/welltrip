## 2. WHY สำคัญ

1. **ทุกหน้าใช้ TanStack Query + wrapper Module 1** — ไม่มี axios ตรง ๆ; error ทุกจุดผ่าน `extractErrorMessage` + แสดง i18n
2. **Filter แบบ staged** (hotels/otop/home-search) — user พิมพ์ใน draft แล้วกดค้นหา = ป้องกัน query ทุกตัวอักษร + กัน date ครึ่งใบส่ง backend
3. **Room add ต้องมีวันที่** — หน้า detail re-fetch อัตโนมัติเมื่อครบ `checkin+checkout` แล้วค่อยปลดล็อกปุ่ม add (payload ต้องมี dates)
4. **Wellness slot.id เป็น int** — ส่งเข้า cart ตรง ๆ โดยไม่ stringify (C3 §3.2) + UI กัน add ซ้ำเกิน capacity_available ด้วย `alreadyInCart()`
5. **OTOP สินค้า stock=0 → disable** (UX guard; backend เช็คซ้ำที่ checkout อยู่แล้ว)
6. **ภาพ** — ถ้า `image_url` ว่าง แสดง placeholder ไอคอน (กันรูปพัง); ยังไม่มี media จริงใน Phase 1
7. **home search = client-side รวม 4 list** — เพราะ backend ไม่มี endpoint search ข้ามหมวด; ตั้งใจให้เป็นแค่ทางลัด

## 3. Known issues / edge cases

- `/hotels` filter ราคา/จำนวนคน ใช้ filter ฝั่ง backend ถูกต้อง แต่ **availability filter ตามวัน ต้องมี checkin+checkout ครบคู่** (backend ปฏิเสธถ้าส่งข้างเดียว — หน้าเช็คก่อนส่ง)
- ราคา/ยอดรวมในหน้าเป็น **estimate**; ยอดจริง = `net_amount` จาก checkout
- Pagination UI แบบ prev/next ใช้ `meta.pagination` (PageNumber) — เลขหน้า 1-based
- `otop` ใช้ `<img>` เฉพาะเมื่อ `image_url` มีค่า — ลองกับข้อมูลจริง ต้องดูว่า URL เป็น absolute หรือไม่
- หน้า foods/otop/wellness list ยังไม่มี detail page (spec ไม่มี) — home search จึงลิงก์ไป `/foods`,`/otop` (list) แต่ wellness/hotels ลิงก์เข้า detail
- `minAvailable === 0` แปลว่า "เต็ม" (availability dict เป็นของเหลือจริง)
- i18n มี key ที่ยังไม่ใช้ (`errorOccurred`, `catalog.filter`, `catalog.price`, `catalog.results`) — เผื่อ Module 5–6
