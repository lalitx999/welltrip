- `Accommodation`: UUID PK, `owner` FK→User **RESTRICT**, slug auto-gen ใน `save()` เมื่อไม่มีการส่งค่า, `checkin/checkout_time` default 14:00/12:00, `status` enum 3 ค่า, `province`/`status` indexed, มีแค่ `created_at` (ตาม spec)

- `RoomImage`: BigAuto PK, FK CASCADE, `image_url` VARCHAR(1000)
- `RoomPricingCalendar`: BigAuto PK, FK CASCADE, `date` indexed, `price_override` nullable, `available_count >= 0`, **Unique `(room, date)`**
- `FoodMenu`: UUID PK, `owner` RESTRICT, `wellness_category` enum 5 ค่า, `calorie_estimate` nullable, `is_available`
- `WellnessService`: UUID PK, `owner` RESTRICT, `duration_minutes >= 1`, `max_capacity_per_session`
- `WellnessTimeSlot`: BigAuto PK, FK CASCADE, `slot_date` indexed, **Unique `(service, slot_date, start_time)`**
- `OTOPProduct`: UUID PK, `owner` RESTRICT, `stock_quantity` PositiveInteger (DB CHECK >= 0), `sku` unique + auto-gen เมื่อไม่ส่งค่า, `is_active`
- `Booking`: UUID PK, `booking_code` format `WT-YYYYMMDD-XXXXXX` (default auto), `user` RESTRICT, `status` enum 5 ค่า (default AWAITING_PAYMENT), `total_subtotal/platform_fee/net_amount`, `expires_at` default = now+15 นาที, `created_at/updated_at`
- `BookingItem`: BigAuto PK, `booking` CASCADE, `item_type` enum 4 ค่า, `entity_id` UUID indexed (**ไม่ใช่ FK** — polyformic), `vendor` FK→User RESTRICT, snapshot ราคา/ชื่อ, `scheduled_date/scheduled_end_date/scheduled_time_slot`
- `Payment`: UUID PK, **OneToOne** → `bookings.Booking` RESTRICT, `payment_channel` enum 2 ค่า, `gateway_charge_id` indexed, `qr_raw_string/qr_image_url`, `amount`, `status` enum 4 ค่า (default PENDING), `paid_at`, `gateway_response_log` JSONB

## 2. การตัดสินใจออกแบบ (WHY)

1. **`owner`/`user`/`vendor` ใช้ `RESTRICT`** — spec §5.3: กัน hard-delete เจ้าของ/ผู้จองที่มีข้อมูล transaction อยู่
2. **`BookingItem.entity_id` เป็น UUID เปล่า** — cart 1 อันอ้างได้หลายตาราง (Room/FoodMenu/WellnessService/OTOPProduct) ใช้ `(item_type, entity_id)` resolve เอาใน services ตอน runtime
3. **Snapshot columns** (`item_title_snapshot`, `unit_price_snapshot`, `total_price`) — freeze ราคาตอนจอง กัน vendor ขึ้นราคาทีหลังแล้วประวัติเพี้ยน
4. **slug/SKU auto-generate ใน `save()`** เมื่อ caller ไม่ส่งค่า — กัน `IntegrityError` (unique+NOT NULL ไม่มี default) แต่ไม่ทับค่าที่ตั้งเอง ใช้ `getattr(self, field, "")` เพราะ field ที่ไม่มี default จะไม่อยู่ใน instance dict
5. **Default ระดับ DB สำหรับค่า "ลืมไม่ได้"** — `booking_code`, `expires_at` (+15 นาที ผ่าน constant `BOOKING_TTL_MINUTES` ให้ Celery Step 4 ใช้ร่วม)
6. **`stock_quantity`/`quantity` = PositiveIntegerField** — Django สร้าง DB CHECK >= 0 ให้ (ZERO TRUST ระดับ DB)
7. **Index พิเศษเกิน spec เฉพาะจุด hot query** — `Booking.status`, `Booking.expires_at`, `BookingItem.entity_id`, `Accommodation.status`, `Payment.status` (กัน slow query)
8. **`image_url` เป็น CharField/TextField ไม่ใช่ URLField** — ให้ค่าความยาวตาม spec (VARCHAR(1000)/TEXT) และรองรับ S3/R2 path

## 6. แผน Step 2 ที่จะทำต่อ (Business Logic — `services.py`)

### การตัดสินใจ/เปลี่ยนโครงสร้างสำคัญ (ระวังตอนทำต่อ)
1. **Payments เปลี่ยนเป็น Slip Check ล้วน** (ตัดสินใจโดย user — ยกเลิก Omise webhook + EMVCo QR ใน Phase 1)
   - Flow: checkout → Payment=PENDING แสดงบัญชีผู้รับ → ลูกค้าโอน/สแกน → อัปสลิป (`PaymentSlip`) → `verify_slip` เรียก provider + เช็คยอด/ref/เวลา → VERIFIED → Payment=SUCCESS + Booking=CONFIRMED
   - `Payment`: channel=`BANK_TRANSFER`, เพิ่ม `payee_account_number/name/bank` (snapshot, ยังว่าง), `created_at/updated_at`; ลบ `gateway_charge_id/qr_*/gateway_response_log`
   - `PaymentSlip` ใหม่: `image` FileField, `provider_reference` + **partial unique index** (VERIFIED) กันใช้สลิปซ้ำ
   - `_call_slip_provider()` **ยังไม่ implement** — รอ vendor + credentials; `verify_slip(provider=...)` inject ได้ (เทสต์ด้วย fake)
   - settings: เพิ่ม `MEDIA_URL`/`MEDIA_ROOT`
2. **`BookingItem.entity_id` เปลี่ยน `UUIDField` → `CharField(36)`** — เพราะ PK ของ `WellnessTimeSlot` เป็น int (BIGSERIAL) แต่ room/food/otop เป็น UUID (spec ขัดกันเอง §2.3 vs §2.4)
   - เก็บ canonical string เสมอ (`str(uuid)` หรือ `str(int)`)
   - **ผลพวง:** Step 4 (rollback/expiry worker) ต้อง cast `entity_id` ตาม `item_type` ก่อน query: ROOM/FOOD/OTOP → `uuid.UUID(...)`, WELLNESS → `int(...)`
3. Checkout (bookings) สร้าง Booking หลัง reserve ครบ; sort items ก่อน lock กัน deadlock; ยัง**ไม่ schedule Celery** (Step 4)
