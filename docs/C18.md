# Module: Centralized System Notifications & Live EasySlip Payment Verification (C18)

## ทำอะไร
- เคลียร์โค้ดทดสอบและจัดโครงสร้างระบบแจ้งเตือนทางอีเมลส่วนกลางของระบบ (`backend/common/notifications.py`) โดยใช้ Hostinger SMTP ส่งอีเมลจริงทั้งหมด ห้ามมี MockupData:
  1. **OTP Verification:** การส่ง OTP 6 หลักสำหรับยืนยันตัวตนสมัครสมาชิกและเปิดร้านค้า
  2. **Admin New Merchant Alert:** แจ้งเตือนแอดมินทันทีเมื่อมีผู้ประกอบการยื่นขอเปิดร้าน
  3. **Merchant Decision Alert:** แจ้งผลการพิจารณา (อนุมัติ/ไม่อนุมัติ) กลับไปยังร้านค้า
  4. **Payment Confirmed (EasySlip):** แจ้งยืนยันการชำระเงินและตั๋ว/การจองแก่นักท่องเที่ยว และแจ้งเตือนร้านค้าเมื่อได้รับเงินโอน
  5. **Slip Rejected Alert:** แจ้งเตือนนักท่องเที่ยวเมื่อสลิปไม่ผ่านการตรวจสอบ (ยอดเงินไม่ตรง, สลิปซ้ำ ฯลฯ) เพื่อให้แนบสลิปใหม่
- วางระบบตรวจสอบสลิปโอนเงินอัตโนมัติด้วย **EasySlip API v1** (อ้างอิง https://document.easyslip.com/) ใน `backend/apps/payments/services.py`:
  - เรียก `POST https://developer.easyslip.com/api/v1/verify` แบบ Multipart Form Data ส่งภาพสลิปจริง
  - ถอดรหัส JSON จริง ตรวจสอบยอดเงิน (`amount`), รหัสอ้างอิงธุรกรรม (`transRef`), วันเวลาที่โอน และผู้รับเงิน
  - ตรวจสอบกฎความปลอดภัยทางการเงิน (Money Rules): ยอดเงินต้องตรงกับยอดจองเป๊ะ, ห้ามเป็นสลิปซ้ำ (`transRef` เคยถูกใช้ไปแล้ว)
  - ลบ MockupData และ Mock fallbacks ออกทั้งหมด

## ทำไมถึงทำแบบนี้
- **ทำไมต้องรวมศูนย์การส่งอีเมลไว้ที่ `backend/common/notifications.py`:** เพื่อไม่ให้โค้ดการสร้างเนื้อหาอีเมลกระจายตัวอยู่ใน views ต่างๆ ทำให้ง่ายต่อการปรับแก้เทมเพลต และสามารถเรียกใช้ซ้ำได้จากทุกแอป (Auth, Bookings, Payments, Admin)
- **ทำไมต้องตัด MockupData ของ EasySlip ออก:** การใช้ Mock data ในระบบการเงินเสี่ยงต่อการเกิดข้อผิดพลาดในการตรวจสอบยอดเงินจริง ระบบจริงต้องพึ่งพา EasySlip API Key ที่แท้จริงจากผู้ดูแลระบบเท่านั้น หากยังไม่ได้ใส่คีย์ ระบบจะแจ้งเตือนอย่างชัดเจนแทนที่จะยอมให้สลิปปลอมผ่าน

## โครงสร้างไฟล์
- `backend/common/notifications.py`: รวมศูนย์ฟังก์ชันส่งอีเมลแจ้งเตือนทุกประเภท
- `backend/apps/payments/services.py`:
  - `_call_slip_provider`: เชื่อมต่อ EasySlip API v1 จริงผ่านไลบรารี `requests`
  - `verify_slip`: ดำเนินการตรวจสอบความถูกต้องทางการเงิน ปรับสถานะการจองเป็น CONFIRMED และสั่งยิงอีเมลแจ้งเตือนนักท่องเที่ยวและร้านค้า
- `backend/apps/payments/views.py`:
  - `slip_upload_view`: ตรวจสอบสลิปอัตโนมัติทันทีที่นักท่องเที่ยวอัปโหลด
  - `admin_approve_payment_view`: รองรับการตรวจสอบด้วยมือจากแอดมิน พร้อมส่งอีเมลแจ้งผล
- `backend/apps/authentication/views.py`: เชื่อมต่อกับ `common.notifications` เพื่อส่ง OTP และแจ้งเตือนแอดมิน

## จุดที่ต้องระวัง
- **EasySlip API Key:** ต้องระบุใน `backend/.env` ใต้ตัวแปร `SLIP_PROVIDER_API_KEY=`
- **Security Check:** ระบบตรวจสอบความซ้ำซ้อนของ `transRef` ทันที ป้องกันการนำสลิปเดิมมาอัปโหลดซ้ำเพื่อโกงการจอง
- **Frontend Git Guard:** ห้ามนำไฟล์ฝั่ง frontend ขึ้น git ตามข้อตกลงอย่างเคร่งครัด
