## 2. ทำไมเลือกแนวทางนี้ (WHY)

1. **Route group ไม่เปลี่ยน URL** — `(mobile-tourist)/home` ยังอยู่ที่ `/home` → redirect หลัง login เดิม (login/register/google callback) และ Landing CTA **ทำงานต่อได้ไม่ต้องแก้**
2. **แยก `MobileBottomNav` เป็น component ใหม่** — มี state ของตัวเอง (active tab + badge) layout เหลือแค่ compose
3. **`pb-[calc(env(safe-area-inset-bottom)+5rem)]`** — กันเนื้อหาท้ายสุดโดน bottom nav ทับ + เผื่อ safe-area ของ iPhone (guardrail)
4. **หน้า /home เป็น shell preview** — reuse `landing.*` keys ที่มีอยู่ ไม่สร้าง keys ใหม่แล้วทิ้ง (Module 4 เขียน Explore feed จริงทีเดียว)
5. **ยังไม่มี auth gate ใน layout** — browsing สาธารณะได้ (backend AllowAny); gate ของ flow เงิน (checkout/my-bookings) ทำที่แต่ละหน้าใน Module 5–6; role-routing ของ vendor มาพร้อม portal (Module 7)

## 3. Known issues / edge cases

- Nav tabs `/hotels`, `/foods`, `/wellness`, `/otop`, `/cart`, `/my-bookings`, `/profile` **ยัง 404** จนกว่า Module 4–6 จะสร้างหน้า (ดูได้จาก shell แต่ยังกดไปไหนไม่ได้จริง)
- `checkout` ติด prefix ของ tab Cart → ระหว่างหน้า checkout bottom nav จะไฮไลต์ "ตะกร้า" (ตั้งใจ)
- `home.*` keys ใน i18n บางตัว (`logout`, `verified` ฯลฯ) **เหลือแต่ยังไม่ถูกใช้** หลังลบหน้าเดิม — เก็บไว้รอหน้า Profile (จะไม่ error เพราะ type-check ดูแค่ความสมมาตร TH/EN)
- Badge ตะกร้า อ่านจาก `useCartStore.itemCount` (Module 2) — ทดสอบได้ตอนมีหน้า cart
