## 3. Endpoint matrix ที่ FE ต้องใช้ (backend มีแล้ว — ตรง C3 §5.3)

### Public (tourist ไม่ต้อง login)
| Method | Path | ใช้กับหน้า |
|---|---|---|
| GET | `/api/v1/accommodations/?province=&checkin=&checkout=&guests=&min_price=&max_price=` | /hotels (list) |
| GET | `/api/v1/accommodations/{id}/rooms/?checkin=&checkout=` | /hotels/[id] (room+availability) |
| GET | `/api/v1/foods/?category=LOW_SUGAR,VEGAN&max_calorie=` | /foods |
| GET | `/api/v1/wellness/` | /wellness |
| GET | `/api/v1/wellness/{id}/slots/?date=YYYY-MM-DD` | /wellness/[id] (เลือกเวลา) |
| GET | `/api/v1/otop/?category=&search=&min_price=&max_price=` | /otop |

### Auth (TOURIST เท่านั้น — flow เงิน)
| Method | Path | ใช้กับหน้า |
|---|---|---|
| POST | `/api/v1/bookings/checkout/` | /checkout |
| GET | `/api/v1/bookings/my-orders/?status=active` หรือ `completed` หรือ `cancelled` | /my-bookings |
| GET | `/api/v1/bookings/{id}/` | /my-bookings/[id] |
| GET | `/api/v1/payments/{id}/` | หน้า payment (ดู payee + slips) |
| POST | `/api/v1/payments/slips/upload/` (multipart: `payment_id` + `image`) | หน้า payment (อัปสลิป) |

> **ทุก list response** มี envelope `{success, data, message, meta.pagination{page,limit,total_items,total_pages}}` — FE ใช้ meta สำหรับ pagination
> **checkout body (C3 §5.5):** `[{item_type, entity_id, quantity, checkin_date?, checkout_date?}]` — `entity_id` ของ WELLNESS = int, ที่เหลือ = UUID string

## 4. Roadmap FE — slices (แนะนำทำทีละ slice + user review/เทสต์)

### Slice FE-1: Foundation — types + domain api + cart-store + layout scaffold
**ไฟล์ใหม่:**
- `src/types/catalog.ts` — Accommodation/Room/Food/Wellness/OTOP types (ให้ตรง serializer output)
- `src/types/booking.ts` — Booking/BookingItem/Payment/CartItem types
- `src/types/api.ts` — `ApiEnvelope<T>`, `PaginationMeta`, `ApiSuccess<T>` (reuse pattern จาก `types/auth.ts`)
- `src/lib/api/catalog.ts`, `src/lib/api/booking.ts` — typed wrappers (เลียนแบบ `auth-api.ts`)
- `src/store/cart-store.ts` — zustand + persist(localStorage) (ดู C3 §7.2 item shape ตรง checkout payload)
- `src/app/(mobile-tourist)/layout.tsx` — MobileBottomNav scaffold + role gate
- เปลี่ยน redirect หลัง login: `/home` → ไป tourist home (ถาม user — ดู §8)

**ทำไม:** ทุกหน้า depend บน types/api/cart — ทำก่อนกันงานซ้ำ

### Slice FE-2: Discovery — /hotels, /hotels/[id], /foods, /wellness, /otop (static lists แรก)
- list pages: query filter UI + TanStack Query `useQuery` + pagination (ใช้ meta)
- /hotels/[id]: room cards + date picker + availability → **ปุ่ม Book → เพิ่ม cart** (ต้องมี cart-store จาก FE-1)
- รูป: ใช้ `image_url` string / `images[]` (ยังไม่มี upload จริง)

### Slice FE-3: Cart + Checkout + Payment
- /cart: รายการ + vendor breakdown + ปุ่ม checkout
- /checkout: สรุป + ยืนยัน → POST checkout → ได้ `booking_id` + `payment_id`
- **/payment/[paymentId]** (route group ยังไม่ชัด — ถาม §8): โชว์ payee (account number ยังว่าง → แสดง placeholder "รอ config" จนกว่า user ให้เลขบัญชี), อัปสลิป (multipart) → poll GET payments/{id} จน slips มี / status เปลี่ยน
- NOTE: ยังไม่มี verify จริง (Slip provider) → UI ต้องรองรับสถานะ "PENDING_CHECK / รอตรวจ"

### Slice FE-4: My Bookings
- /my-bookings: tabs ACTIVE/COMPLETED/CANCELLED (map ไป `?status=` backend ที่ทำไว้)
- /my-bookings/[id]: detail (items + payment status + payee)

### Slice FE-5: Vendor Portal (Step 7 — **ต้องมี API เพิ่มก่อน! ดู §7 blocker**)
- `(portal)/layout.tsx` — sidebar + role-based menu
- homestay/restaurant/wellness/otop dashboards (เท่าที่ API มี)

### Slice FE-6: Deliverable + cleanup
- `phase1-remaining-summary.md` + typecheck/build สุดท้าย

## 5. Guardrails / กติกาที่ห้ามละเมิด (ทุก slice)

- **อ่านโค้ดจริงก่อนเสมอ** — `frontend/src/globals.css` (theme token), `tailwind.config.ts`, `lib/i18n.tsx` (วิธีเพิ่ม key 2 ภาษา)
- **i18n:** ข้อความทุกตัวผ่าน `useI18n().t(...)`; เพิ่ม key ให้ครบ `en` + `th` (th ต้อง type-check ตรง en)
- **ห้าม Emoji** — ใช้ Lucide เท่านั้น (spec §7.2 มีตาราง icon: Hotel/BedDouble/UtensilsCrossed/Salad/Sparkles/ShoppingBag ฯลฯ)
- **envelope:** ทุก api call ต้อง handle `{success:false, error, message}` (ใช้ `extractApiErrorMessage` จาก auth-api — ย้าย/แชร์ถ้าจำเป็น)
- **SECURITY:** token อยู่ token-manager ไม่แยก; อย่า hardcode secret/URL (ใช้ `NEXT_PUBLIC_API_BASE_URL`)
- **Zustand** สำหรับ global state (cart) + persist; **TanStack Query** สำหรับ server cache (ไม่ทำซ้ำ)
- หลัง login: ตรวจ `role` → นำทางถูก (tourist → mobile-tourist, vendor → portal)
- อย่าแตะ auth files ที่เทสต์ผ่าน (`use-auth`, `auth-api`, `api-client`) เว้นจำเป็น — ถ้าจะแตะ ถามก่อน (DISSENT)

## 7. Blocker ที่ต้องแก้/ถามก่อนทำบาง slice

1. **Portal ต้องมี API เพิ่ม** (ยังไม่มี — ถาม user):
   - vendor ดู "incoming orders" (C3 §9 เขียนชัด: ยังไม่มี endpoint ต้องออกแบบ เช่น `GET /vendor/orders/?role=...`) — **ห้ามเดาเอง**
   - PATCH/edit ของ vendor (food toggle is_available, otop edit, wellness close slot) — ยังไม่มี
2. **Route สำหรับหน้า payment:** C3 §7.2 แนะนำ `(mobile-tourist)/checkout/payment/[bookingId]` แต่ backend ตอนนี้ให้ `payment_id` ต่างหาก → **ถาม user** ว่าจะให้หน้า payment ใช้ bookingId หรือ paymentId (backend GET /payments/{id} ใช้ payment_id; booking detail มี payment.id ใน response → FE map ได้)
3. **เลขบัญชี payee ยังว่าง** → หน้า payment ต้องแสดง placeholder "รอระบบตั้งค่าบัญชี" หรือซ่อนส่วนโอน จนกว่า user ให้เลขบัญชีจริง (backend `payee_*` ยัง empty string)
4. **Slip upload ยังไม่มี verify จริง** → UI ต้องบอก user ว่า "อัปสลิปแล้ว รอตรวจ" ไม่มี auto-confirm จนกว่ามี provider
5. **Google OAuth ยังไม่ได้ตั้งค่า client จริง** (C1 TODO) — ถ้า FE จะเทสต์ Google flow ต้อง config console ก่อน
