# Module: Merchant OTP Verification & Sandbox Approval Workflow (C17)

## ทำอะไร
- ระบบส่งรหัส OTP 6 หลักเข้าอีเมลของผู้ประกอบการที่ขอเปิดร้านค้า เพื่อยืนยันว่าอีเมลมีตัวตนจริงและเป็นเจ้าของอีเมล ก่อนกดส่งใบสมัคร
- ระบบส่งอีเมลแจ้งเตือน (Admin Alert) ไปยังทีมงานแอดมินทันทีเมื่อมีร้านค้ายื่นขอเปิดร้าน เพื่อให้แอดมินเข้าตรวจสอบข้อมูลและอนุมัติ (Approve) ได้ทันท่วงที
- การจำกัดการแสดงผลในหน้าแคตตาล็อกสาธารณะ (Sandbox Gating): ในระหว่างรออนุมัติ ร้านค้าสามารถล็อกอินเข้าสู่ระบบ Merchant Portal (`/portal`) ตกแต่งร้าน เพิ่มห้องพัก อาหารเพื่อสุขภาพ บริการเวลเนส และสินค้า OTOP ได้ตามปกติ แต่สินค้า/บริการเหล่านี้จะยังไม่แสดงต่อนักท่องเที่ยวทั่วไปจนกว่าจะได้รับการอนุมัติจากแอดมิน
- ระบบส่งอีเมลแจ้งผลการพิจารณา (Approval / Rejection Email) กลับไปยังร้านค้าเมื่อแอดมินกดอนุมัติหรือปฏิเสธ พร้อมเปิดใช้งานรายการห้องพักและบริการสู่สาธารณะทันทีอัตโนมัติ

## ทำไมถึงทำแบบนี้
- **ทำไมต้องมี OTP ทางอีเมล:** ป้องกันการสแปมสมัครบัญชีร้านค้าด้วยอีเมลปลอม หรือการกรอกอีเมลผิดพลาด ซึ่งจะทำให้ร้านค้าไม่ได้รับการแจ้งเตือนและการติดต่อที่สำคัญ
- **ทำไมต้องมี Sandbox Onboarding:** ผู้ประกอบการต้องการเตรียมความพร้อม ตั้งชื่อร้าน อัปโหลดรูปภาพ จัดการเมนู และราคาล่วงหน้า การให้ตกแต่งร้านได้ทันทีจะช่วยลดความล่าช้า (Friction) ในการเริ่มใช้งาน ขณะเดียวกันระบบก็ยังต้องรักษาคุณภาพและความปลอดภัยของแพลตฟอร์มด้วยการไม่เปิดให้ข้อมูลที่ไม่ผ่านการตรวจแสดงสู่สาธารณะ
- **ทางเลือกอื่นที่คิดไว้:**
  1. *รออนุมัติก่อนค่อยให้เข้าล็อกอิน:* ผู้ประกอบการจะรู้สึกเคว้งคว้างและต้องรอเฉยๆ ทำให้เสียเวลาเริ่มต้นธุรกิจ
  2. *อนุมัติอัตโนมัติทันที:* เสี่ยงต่อร้านค้าปลอมและข้อมูลที่ไม่ถูกต้องซึ่งส่งผลต่อความน่าเชื่อถือของแพลตฟอร์ม

## โครงสร้างไฟล์
- `backend/core/settings/base.py`: ตั้งค่า Hostinger SMTP (`smtp.hostinger.com:465` SSL) พร้อมตัวแปรสภาพแวดล้อม
- `backend/apps/authentication/models.py`: โมเดล `EmailVerificationOTP` (เก็บ `email`, `otp_code`, `purpose`, `is_used`, `expires_at`)
- `backend/apps/authentication/migrations/0003_emailverificationotp.py`: ไฟล์ Migration สำหรับตาราง OTP
- `backend/apps/authentication/views.py`: 
  - `request_email_otp_view`: Endpoint สุ่มรหัส 6 หลัก ส่งเมลผ่าน Hostinger และจำกัด Rate limit 60 วินาที
  - `verify_email_otp_view`: Endpoint ตรวจสอบความถูกต้องของ OTP
  - `register_merchant_view`: บังคับตรวจ OTP ก่อนบันทึกผู้ใช้ + ส่งอีเมลแจ้งเตือนแอดมิน
  - `admin_approval_action_view`: ปรับสถานะร้านค้า, ปรับสถานะห้องพักเป็น ACTIVE และส่งอีเมลแจ้งผลไปยังร้านค้า
- `backend/apps/services/views.py` & `backend/apps/otop/views.py`: กรองไม่ให้สินค้าของร้านค้าสถานะ PENDING/REJECTED แสดงใน Public Catalog
- `frontend/src/lib/auth-api.ts`: API Client สำหรับส่ง/ยืนยัน OTP
- `frontend/src/app/(auth)/register/merchant/page.tsx`: UI Step 2 เพิ่มกล่องขอรับรหัส OTP พร้อมปุ่มจับเวลาถอยหลัง 60 วินาที

## จุดที่ต้องระวัง
- **รหัสผ่านอีเมล Hostinger:** ต้องใส่รหัสผ่านที่ถูกต้องใน `backend/.env` ใต้ `EMAIL_HOST_PASSWORD` มิฉะนั้นระบบจะส่งเมลไม่สำเร็จ
- **Rate Limit:** การกดขอ OTP ซ้ำๆ ถูกป้องกันไว้ที่ 60 วินาที เพื่อไม่ให้เซิร์ฟเวอร์ SMTP ถูกบล็อก
- **อายุของรหัส OTP:** รหัสมีอายุ 10 นาที หากเกินเวลาต้องกดขอรหัสใหม่
